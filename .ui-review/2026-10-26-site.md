# UI review — whole site (2026-10-26)

**Answer:** The site works and is fast to use (every measured press responds in 24–56 ms, no overflow
or console errors on any of 17 routes), but two things are broken for real users: the student request
form is not a proper dialog for keyboard and screen-reader users, and every network failure is shown
to students as a false fact ("no free seats", "no requests for this number").

**Ready to ship: no.** The request form lets focus escape and loses it on close, and API failures read as
"library full" / "no requests" (blocking 2, should-fix 4, notes 9, 5 questions for a person).

## 2. Findings

### Blocking

**B1 — The student request form is not a dialog for keyboard or screen-reader users.**
Raised by: reviewer (solo). Criterion 8 Keyboard & focus, 12 Semantics.
- Seen: opening `button 'Request desk 1 ▶'` (browse, 1280) puts focus in `#req-name` (good), but the sheet has
  **no `role="dialog"` / `aria-modal`**, **focus left the sheet on 26 of 40 Tab presses**, and after Escape
  focus landed on `button '55'` (a desk on the plan behind it), not on the button that opened it.
- Why it matters here: this is the only form the public can fill in, and the one that brings in members.
  A keyboard user tabs into the dimmed plan behind the form; a screen reader is never told a dialog opened.
- Evidence: `raw.json` → `probes.sheetDialogRole = "no role=dialog"`, `sheetFocusEscapes = 26`,
  `focusAfterClose = BUTTON "55"`. Component: `components/seat/SeatRequestSheet.tsx`.
- Fix so that: the sheet has `role="dialog" aria-modal="true" aria-labelledby` its title; 0 of 40 Tab presses
  leave it; Escape returns focus to `Request desk N`.

**B2 — Network failures are shown to students as false facts.**
Raised by: reviewer (solo). Criterion 9 States (error).
- Seen, with `/api/members` returning 500: `/browse` shows **"Free 0 / 0"** and **"No free seats right now"**
  (`probe-browse-error-390.png`); `/landing` hero says **"Seats free 0 / 95"** (`probe-landing-api-down-390.png`).
  With `/api/requests/my` returning 500, `/my-requests` says **"No requests for this number"**
  (`probe-my-requests-error-390.png`).
- Why it matters here: a student is told the library is full, or that their request does not exist, when the
  server merely hiccupped. The same path fires on a 429 (rate limit) and on a phone with bad signal.
- Evidence: `useMembers()` returns `isError`, but no page reads it (`grep useMembers() app` — every call
  destructures only data/isLoading). `lookupByPhone` returns `[]` on `!res.ok` (`hooks/useSeatRequests.ts:129`).
- Fix so that: with `/api/members` → 500, `/browse` and `/landing` show "Couldn't load the seat plan" with a
  Retry button and no counts; with the lookup → 500/429, `/my-requests` says "Couldn't check right now" and
  keeps the number typed.

### Should-fix

**S1 — Member initials on the staff seat plan fail contrast.**
Criterion 6. axe `color-contrast` on 56 desks at `/` 1280 and 9 at `/floorplan` 390
(e.g. `button 'Seat 2, Aarav Sharma, Active' > span`). Cause: `text-[11px] … opacity-80` at
`components/seat/SeatTile.tsx:99`. The initials are how staff recognise who sits where.
Fix so that: axe reports 0 `color-contrast` nodes on `/` and `/floorplan` (drop the opacity, use the status
text token at full strength).

**S2 — Activity log is unusable on a phone.**
Criteria 11, 8. At 390 the table squeezes: Details wraps one word per line ("Admin / (owner) / signed / in")
and the Time column is cut off (`audit-390.png`). The scroll container is not keyboard-reachable
(axe `scrollable-region-focusable`, `app/audit/page.tsx:96`).
Fix so that: at 390 each row is a card (action, details, seat, time all visible without sideways scroll), and
axe reports no `scrollable-region-focusable` on `/audit`.

**S3 — Renewals hides its action buttons on a phone.**
Criterion 11. At 390 the table clips after "Urgency / Statu…" — the Renew / WhatsApp / Vacate buttons are
off-screen (`expiry-390.png`). This page exists to press those buttons.
Fix so that: at 390 every row shows member, days overdue and a reachable Renew button (card layout like
Members already uses).

**S4 — The request confirmation disappears after 2.2 seconds.**
Criterion 10 Feedback. `components/seat/SeatRequestSheet.tsx:149–163` closes the "Request sent" state on a
2200 ms timer. A student reading the next steps (pay at desk, track under My requests) loses them mid-read.
Fix so that: the confirmation stays until dismissed and shows desk, plan, amount and a "Track it under My
requests" link.

### Notes

- **N1** Public header on a phone shows only "My requests"; Seats and Fees are `hidden md:inline-flex`
  (`landing-390.png`). Students rely on the hero button. (criterion 1)
- **N2** The seat-plan skeleton is a grid of rounded squares that then becomes the room plan
  (`probe-browse-loading-390.png`) — the layout jumps on load. A plan-shaped skeleton would not. (9)
- **N3** Footer links "Seats" / "My requests" are 20 px tall (`landing-390.png`) — under the 24 px target, but
  spaced 24 px apart so WCAG 2.5.8's spacing exception likely holds. (7)
- **N4** The public plan makes each free desk a Tab stop (24 stops before the side panel). A roving tabindex
  with arrow keys would be one stop — `nextSeatInDirection` already exists in `lib/layoutConfig.ts`. (8)
- **N5** Members at 1280 interleaves 24 "(Vacant)" rows between members (`members-1280.png`). (1)
- **N6** Activity log fills with repeated "Signed In" rows (`audit-1280.png`); the actions that matter
  (payments, renewals) get pushed down. (1)
- **N7** Reading hall at 390 jumps from h1 to h3 (axe `heading-order`). (12)
- **N8** Members table has an empty header cell (axe `empty-table-header`, checkbox/actions column). (12)
- **N9** `/floorplan` renders two `<main>` landmarks (axe `landmark-no-duplicate-main`,
  `app/floorplan/page.tsx:214` inside the shell's main). (12)

- **Focus rings (8):** every Tab stop measured on `/landing` (14) and `/browse` (16) drew a visible ring.
- **Layout (11):** no horizontal overflow on any route at 390 or 1280; no console errors.
- **Reduced motion:** `/landing` and `/browse` run no animations under `prefers-reduced-motion: reduce`.

## 4. For a person to decide

1. **Setup page** still explains a Google Forms + Apps Script flow ("Connect Google Forms for automated seat
   allotment") next to the built-in request form. Keep it, hide it, or remove it?
2. **Contact details on the public site:** there is no phone, WhatsApp or address anywhere (`lib/siteInfo.ts`
   is empty), so a student with a question has no way to reach the library. Needs the real details.
3. **Real photos and reviews** (`lib/photos.ts`, `SITE_INFO.reviews`) — the single biggest trust gain on the
   landing page, and only the owner can supply them.
4. **Analytics stat tiles** put `<dt>/<dd>` inside `<button>` (axe `definition-list`, `dlitem`,
   `app/analytics/page.tsx:149,484`). Fixing it restructures the accessibility tree — approve the change.
5. **Phone navigation** for students: show "Seats" in the header, or add a small menu?

## 5. Dismissed and left out

- Attendance runs 8 animations under reduced motion — dismissed: they are opacity-only entrance fades, which
  `AppShell`'s `MotionConfig reducedMotion="user"` keeps on purpose ("gentler, not zero").
- `/setup` contrast (1 node) and colour-only "Google Forms" link (axe `link-in-text-block`) — left out pending

- Taste-level remarks (more whitespace, different hero) — left out, no criterion.

## 6. Beyond the fixes — what a senior frontend engineer would do next

Ordered by impact for this library, each sized honestly.

1. **One "data state" pattern for every screen** (½ day). A small `<DataState loading empty error onRetry>`
   used by every SWR hook: skeletons shaped like the real content, errors with Retry and the request id
   (`x-request-id` is already sent), empty states that say what to do next. Fixes B2 and N2 everywhere at once.
2. **Make the request form a real sheet** (½ day). Radix Dialog is already a dependency: focus trap, return
   focus, `aria-modal`, Escape — fixes B1. On phones, a bottom sheet with drag-to-dismiss; the confirmation
   becomes a "ticket" (desk, plan, amount, UPI ref, what happens next, share on WhatsApp) that stays (S4).
3. **Keyboard-first seat plan** (½ day). Roving tabindex + arrow keys using `nextSeatInDirection`, Enter to
   select, a polite live region ("Desk 41 · Column 4 · free"). Fixes N4, and the plan becomes usable without
   a mouse — staff at a busy desk will use it.
4. **Phone layouts for the two staff tables** (½ day). Activity log and Renewals as card lists, like Members
   already is (S2, S3).
5. **Motion that explains, inside design.md's limits** (1 day). The selected desk "lifting" into the side
   panel via the View Transitions API, a toast that slides from where the action happened, number tickers on
   the dashboard counts when filters change — all honouring reduced motion. This is where "stunning" comes
   from without decoration.
6. **Trust on the landing page** (owner input). Real photos of the hall, a WhatsApp button, a Google Maps
   card, two or three real student quotes. No design change beats a real photo of the actual desks.
7. **Staff speed** (1–2 days). The ⌘K search already exists — let it run actions ("renew 41", "mark 12
   paid"), add a "Today" card (renewals due, money owed, requests waiting), and one-tap bulk WhatsApp reminders
   once a provider is connected.
8. **Lock it in** (½ day). Commit this capture script as `npm run check:ui` with baseline screenshots and axe,
   and run it in the GitHub Action, so a future change cannot quietly break the 390 px layouts or contrast.

Coverage: 17 routes × 390 and 1280 (34 captures + accessibility trees + axe); light theme; probes measured —
keyboard Tab path (/landing, /browse), dialog semantics, focus trap and focus-after-close (request form),
slow-network and 500-error states (/browse, /landing, /my-requests), reduced motion (/landing, /browse,
/attendance), Event Timing (/browse, /, /members). Not measured: 200 % zoom, offline, throttled CPU, screen
reader speech output, 429 on lookup, full-library and empty-queue states, Largest Contentful Paint.
